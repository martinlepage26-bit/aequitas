# Case agent (2026-11-06)

Status: **off by default; tested on synthetic data with a stub model only.** No live model has been evaluated. Do not enable it for real cases before the decisions at the end of this page are made.

## Routine path it handles without a case manager

All workflow decisions are deterministic code under the program's configured rules (`src/domain/caseAgent/config.ts`). The model drafts a staff summary, picks a remedy from a closed list, and supplies staff-only, evidence-linked reasons for that proposal. Each party receives fixed wording; neither the rationale nor the other party's evidence links are shown to them. Every step below is a separate scheduled pass (`npm run agent:run`); each pass is idempotent and re-checks the case row under lock.

1. **Take the case.** A submitted `OPEN` case with no assigned manager is taken by the agent (`agent_open_intake`) only if it is `RETAIL` and its amount at stake is present and within the program limit. Anything else stays in the normal case-manager queue untouched. Both parties receive an explicit bilingual notice by email and on the case page: the agent handles routine steps, proposals are not binding, are not legal advice and do not judge truthfulness, participation is voluntary, and either party can ask for a person or end participation.
2. **Invite the respondent.** The agent creates the existing respondent invitation and an encrypted delivery payload in one transaction (`PARTY_NOTIFIED` event, same invitation tables and email as the complainant-initiated path). It tries delivery immediately. If Resend is temporarily unavailable, the message stays queued for the scheduled mail worker; a permanent rejection, exhausted retry budget, or respondent who does not join within the response period sends the case to a person.
3. **Collect evidence.** Parties upload through the existing evidence form: MIME allowlist, size limits, ClamAV scan, hash recorded. Each party must mark their own evidence intake complete; a new submission clears that party's mark, and a case-detail change clears both. The agent closes intake (`agent_close_intake`) only after both current marks and at least one clean item from each party, then queues a bilingual request for each party to submit or update their position. It can close as soon as both are ready. At the configured maximum period, an incomplete submission or a party who has not marked complete goes to a person; silence never counts as readiness. A pending scan makes it wait until that period ends, then goes to a person. A rejected file goes to a person immediately.
4. **Collect positions and ask about provider processing.** Parties submit positions as usual. A missing position after the response period goes to a person. Once both positions are in, each party sees the configured provider and model, the exact notice in their selected language, and a separate acceptance button. The service does not extract evidence files or send positions or extracted file text to the model provider until both parties accept the current provider, prompt version, and bilingual notice. Each choice is an append-only `AGENT_PROCESSING_ACCEPTED` event that records its author, exact notice text, locale, provider identity, prompt version, and notice hash; parties cannot see the other party's choice. A provider, model, prompt, or notice change makes earlier choices no longer valid. Either party can request a person instead; if both choices are not recorded by the response deadline, the case is handed to staff.
5. **Read the evidence and propose.** Only after both processing choices match, and before any model call, the agent:
   - downloads every current clean item and checks its stored size and SHA-256
   - extracts text (see below)
   - stops for a person if anything is unreadable, partial or over the limits

   The model returns a staff-only summary and reasoning as separate claims, a structured proposal (`refund_full`, `refund_partial`, `store_credit`, `replacement` or `repair`, plus an amount where one applies), atomic proposal-basis claims, citations with exact excerpts, and the evidence each party's outcome relies on. Every summary, reasoning, and proposal-basis claim must point to one or more citation IDs; the stored record preserves those claim-to-quote links. Deterministic checks then require:
   - a strict schema with no extra fields
   - every excerpt appearing exactly once in the cited file's extraction
   - every summary, reasoning, and proposal-basis claim pointing to an existing exact-quote citation, with no unlinked citation
   - each party's outcome pointing only to that party's own evidence
   - an amount that is needed by the remedy and not above the amount at stake
   - no verdict, credibility, score, legal-advice, binding or pressuring language in any model text

   A failed check goes to a person; nothing is partially written.
6. **Issue.** One locked write (`agent_issue`) stores the recommendation, both party outcomes, per-outcome citation pointers and notifications. If any material the model saw changed during the call, the result is discarded as stale and redone on the next pass.
7. **Answers.** Parties consent or decline through the existing consent flow, which binds each answer to the outcome version. Independent approver sign-off remains required unless the program explicitly sets `AEQUITAS_CASE_AGENT_CONSENT_ONLY_RESOLUTION=true` after owner and governance approval. An unanswered proposal after the response period goes to a person.
8. **Close.** After both parties consent, or after either party ends participation, the agent generates the sealed export and closes the case (`agent_close`). A decline goes to a person; the agent never closes a declined case.

## Handoffs to a person

The agent stops, records `AGENT_ESCALATED` with a reason, and notifies the assigned case manager. If no manager is assigned, it notifies every case-manager account with a passkey (the program's queue). An unassigned escalated case appears in every case manager's list; one manager takes it by declaring no conflict of interest (`POST /api/cases/[id]/claim`). From then on, normal human rules apply, including approver sign-off.

Reasons:

| Area | Reasons |
|---|---|
| Party choice | `party_request` (either party, any time before closure), `processing_choice_timeout` (both did not accept the provider disclosure before the deadline), `declined` |
| Invitation and timing | `invitation_failed`, `respondent_no_response`, `submission_missing`, `intake_incomplete`, `evidence_scan_pending`, `no_answer` |
| Scope | `out_of_scope_category`, `out_of_scope_amount` |
| Evidence | `evidence_rejected`, `evidence_inadequate`, `evidence_extraction_failed`, `evidence_limit_exceeded` |
| Process | `contestation_open` |
| Program configuration | `program_rules_incomplete` |
| Model and capacity | `model_unavailable`, `model_failed`, `model_requested_review` (including unresolved material-fact conflicts), `model_output_rejected`, `daily_model_call_limit_reached`, `model_budget_unavailable` |

## Evidence the agent actually reads

The agent reuses the existing pipeline in `src/lib/evidenceText.ts`:

| Format | Method | Notes |
|---|---|---|
| `text/plain` | UTF-8 decode | |
| PDF | `pdftotext` for text-only pages; `pdfimages` detects pages with embedded images, which are rendered with `pdftoppm` and OCRed with `tesseract` as a whole page | Up to 20 pages. A longer file is "partial" and goes to a person. The page number is recorded with each citation. OCR may misread text. |
| PNG, JPEG, TIFF, WebP | `tesseract` OCR | Languages from `AEQUITAS_OCR_LANGUAGES`. OCR text is cited as extracted, not corrected. Static rasters only; multi-page TIFF and animated PNG/WebP go to staff. |

- **Limits:** 25 MiB per file, 12 MP and 12,000 pixels per axis for direct image OCR, 12,000 characters per source, 12 files and 60,000 characters per case. Malformed image headers, animated PNG/WebP, multi-page or BigTIFF files and any other unreadable, partial or over-limit extraction go to a person.
- **Not read:** any page that remains empty after OCR, other formats (unsupported), and any truncated extraction. Each of these goes to a person. A filename or description is never treated as proof. When a page contains an embedded image, OCR replaces that page's text-layer extraction so visible text and scanned content are assessed together.
- **Citations:** each records a stable response citation ID, evidence id, start and end character offsets, the source-file SHA-256, the extracted-text SHA-256, the extraction method and, for PDFs, the page. Summary, reasoning, and proposal-basis claims reference these IDs. A party opening a cited outcome excerpt gets it re-extracted and re-verified against both hashes. Citation digests are bound to the issuance event and checked by `verifyCase`.
- **What the links prove:** they make it possible to trace each staff summary, reasoning, or proposal-basis claim to an exact excerpt in a hash-verified extraction. They do not prove that the excerpt semantically supports the claim, or that the document is authentic, accurate or relevant. Staff review and live-model evaluation are still required.

## Privacy and party choice

- **Fixed party text.** No model-written sentence reaches a party. Each party reads fixed French or English wording generated from the structured proposal (`src/domain/caseAgent/proposal.ts`), plus excerpts from their own evidence only. The summary, reasoning and citation notes stay with staff. This replaces the earlier six-word overlap check, which could not prove that a paraphrase leaked nothing.
- **Provider processing choice.** The per-case agent panel shows the configured provider and model and the program-supplied notice in English or French. The case agent waits for separate choices from both parties before extracting evidence files or sending positions or extracted evidence text to that provider. Each choice records the exact notice text and its provider, prompt, and notice identity in the append-only event log; a changed provider, model, prompt version, or notice invalidates prior choices. Missing configuration keeps the agent off; a party can ask for a person instead. This product control does not establish legal sufficiency or replace provider, privacy, or counsel review.
- **Isolation rules unchanged.** The existing submission-visibility contract still applies: parties never see the other side's submissions, outcome or request for a person.
- **Ending participation.** Either party can request a person until closure. The complainant can always end participation. The respondent can on agent-managed cases when the program setting `AEQUITAS_CASE_AGENT_RESPONDENT_MAY_WITHDRAW` is `true`; there is no default. Human-managed cases keep the existing complainant-only withdrawal rule.

## Permissions

- **Account.** The agent acts as one `CASE_AGENT` service account (`npm run agent:provision`). No session can be issued for that role and it has no passkey.
- **State machine.** It holds exactly `agent_open_intake`, `agent_close_intake`, `agent_issue` and `agent_close`, each guarded by `agentMayAct` (opted in, not escalated, actor is the agent). A unit test asserts it holds nothing else.
- **No case access.** `caseReadAccess` gives it nothing, so it cannot use any route.
- **What it cannot do.** Tests show it cannot consent, decline, approve, write outcomes as a manager, request a person, or administer users.
- **Audit.** Every agent write appends hash-chained events attributed to the agent, with the model id, the prompt version (`case-agent-2026-11-06.3`) and a digest of the material it saw. Summary, reasoning, and proposal-basis claims link to verified extracted excerpts for staff review and are removed from party views. These exact links make review traceable; they do not prove that an excerpt semantically supports a claim.

## Program configuration (no defaults)

| Setting | Meaning |
|---|---|
| `AEQUITAS_CASE_AGENT_ENABLED=true` | Program-level switch. |
| `AEQUITAS_CASE_AGENT_MAX_AMOUNT_CENTS` | Largest amount at stake the agent may handle. |
| `AEQUITAS_CASE_AGENT_MAX_MODEL_CALLS_PER_UTC_DAY` | Required positive integer. Maximum outbound proposal-model call attempts across all workers per UTC day. Every reserved attempt counts, including provider failures; reaching the limit hands cases at the proposal step to staff. |
| `AEQUITAS_CASE_AGENT_INTAKE_DAYS` | Maximum time from opening intake to complete evidence and mark both sides ready; an incomplete case goes to a person when it expires. |
| `AEQUITAS_CASE_AGENT_RESPONSE_DAYS` | Time to join after an invitation, to submit a position, and to answer a proposal. |
| `AEQUITAS_CASE_AGENT_RESPONDENT_MAY_WITHDRAW` | `true` or `false`. |
| `AEQUITAS_CASE_AGENT_CONSENT_ONLY_RESOLUTION` | `true` only if the owner explicitly approves removing independent approver sign-off for routine agent-managed cases; `false` keeps sign-off. This setting is recorded on each enrolled case. Escalation always restores the normal approval requirement. |
| `AEQUITAS_CASE_AGENT_PROCESSING_NOTICE_EN` / `AEQUITAS_CASE_AGENT_PROCESSING_NOTICE_FR` | Required, operator-supplied bilingual provider-processing notice, each at most 3,000 characters. The page separately displays the provider and model. Review the exact wording with the program and counsel before real cases; the application does not determine whether it is legally sufficient. |
| `GEMINI_PROJECT_ID` | Required for Gemini case data. The operator identifies and verifies the project that owns the configured API key; the app cannot inspect that mapping. |
| `AEQUITAS_AI_PROVIDER_TERMS_REVIEWED_FOR` | Required before the agent sends case material. It must exactly match `gemini:<project-id>:<model>` or `workers-ai:<account-id>:<model>`. A change to provider, account/project or model fails closed until the terms are reviewed again. This is an operator attestation, not privacy or legal approval. |
| `AEQUITAS_GEMINI_PAID_TIER_CONFIRMED_FOR` | Also required for Gemini. After confirming the exact API-key project has active billing and Paid Tier terms, set it to the same value as `GEMINI_PROJECT_ID`. The app cannot verify the provider billing tier or key-to-project mapping. |
| `AEQUITAS_CASE_AGENT_EVALUATION_REVIEWED_FOR` | Required before the runtime can manage cases. Set it only after a successful live synthetic evaluation has been reviewed by the owner, operator, counsel and a Québec French reader as appropriate. Its exact value is `<provider-identity>:prompt:<AGENT_PROMPT_VERSION>`, for example `workers-ai:<account-id>:@cf/google/gemma-4-26b-a4b-it:prompt:case-agent-2026-11-06.3`. A provider, account/project, model or prompt-version change invalidates the attestation. |

If program rules are missing or invalid, the agent takes no new case and hands active agent-managed cases back to staff. New cases also wait in the normal queue until an approved provider is configured. Email delivery must be configured for the respondent invitation; otherwise the case goes to a person.

The daily call ceiling is enforced with an atomic PostgreSQL counter shared by all scheduler workers and resets at 00:00 UTC. The counter stores only one aggregate row per UTC day, with no case or party identifiers. It limits call volume, not dollars: model prices and token use vary, so operators must also configure provider-side spend alerts or limits. When capacity is exhausted, new open cases stay in the ordinary case-manager queue; cases already managed by the agent are handed back at the proposal step. If the usage store cannot be checked, new cases stay in the ordinary queue, active cases are handed to staff, and the agent makes no model request. A missing or invalid processing notice is part of incomplete program configuration; active agent-managed cases return to staff rather than proceeding without the party choices.

**Runtime model.** The agent uses the existing `TextCompletion` interface: Gemini (`GEMINI_API_KEY`, optional `GEMINI_MODEL`) or Cloudflare Workers AI (`CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_API_TOKEN`, optional `AEQUITAS_WORKERS_AI_MODEL`), selected by `AEQUITAS_PIPELINE_PROVIDER`. Anthropic and OpenAI are refused on this path. Calls are billed to the deployment's own provider account, not to Claude Code Cloud credits. Current provider data terms and transfer conditions still require program and counsel review.

For Workers AI, the case agent supplies its output schema as one required function call, with a 16,000-token request ceiling. Cloudflare documents the OpenAI-compatible `/v1/chat/completions` endpoint; its Gemma 4 model page lists function calling and `tool_choice: required`, which matches the adapter's request shape. The application still parses the result through the same strict Zod schema and checks every citation and program rule; a missing, malformed or unexpected tool call is handed to a person. Function calling improves output shape but does not establish factual accuracy, neutrality or French quality. This adapter is covered by mocked tests only: the official contract documentation supports the request format, but an authenticated call against the selected account and the live response shape still need the gated synthetic evaluation ([Cloudflare OpenAI-compatible endpoints](https://developers.cloudflare.com/workers-ai/configuration/open-ai-compatibility/), [Cloudflare function calling](https://developers.cloudflare.com/workers-ai/features/function-calling/traditional/), [Gemma 4 model details](https://developers.cloudflare.com/ai/models/%40cf/google/gemma-4-26b-a4b-it/), [JSON Mode model list](https://developers.cloudflare.com/workers-ai/features/json-mode/), [Workers AI model input limits](https://developers.cloudflare.com/api/resources/ai/methods/run/)).

Exceptions include application logging, AI Gateway logging or caching, storage products, asynchronous or batch features, and other stateful features. The selected evaluation candidate is now `@cf/google/gemma-4-26b-a4b-it`; Cloudflare's model page marks it zero-data-retention and lists $0.10 per million input tokens and $0.30 per million output tokens. Google's Gemma 4 model card identifies Apache 2.0, and Google's overview says responsible commercial use is permitted. This is model-license evidence only; it does not constitute legal approval for Aequitas or review Cloudflare's service agreement. French and Québec French quality remains untested ([Workers AI data usage](https://developers.cloudflare.com/workers-ai/platform/data-usage/), [Gemma 4 model page](https://developers.cloudflare.com/ai/models/%40cf/google/gemma-4-26b-a4b-it/), [Gemma 4 Apache 2.0 license](https://ai.google.dev/gemma/apache_2), [Gemma 4 overview](https://ai.google.dev/gemma/docs/core.md), [current pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/)).

For the first live evaluation, Cloudflare Workers AI remains the preferred candidate because its published standard-inference retention commitment is narrower. The previous default, `@cf/meta/llama-3.1-8b-instruct-fp8`, is scheduled for deprecation on November 15, 2026, so the code now defaults to Cloudflare's current Gemma 4 candidate before the evaluation begins. Cloudflare currently includes 10,000 free Neurons per day on its Workers Free plan; requests beyond that limit fail unless the account uses Workers Paid, where usage above the free allocation is charged. Gemma 4 is not listed among the models requiring a paid billing method on the current pricing page. Use a test account on Workers Free and synthetic cases only so the evaluation cannot create paid overage; if Workers Paid is used, configure a spend limit. This is a provider-fit recommendation only: it does not establish data residency, satisfy counsel review, authorize a live call, or permit real case data. The operator must verify the exact account, model license, logging configuration and current agreement before setting `AEQUITAS_CASE_AGENT_EVAL_APPROVED=true` ([Workers AI pricing and limits](https://developers.cloudflare.com/workers-ai/platform/pricing/), [deprecation notice](https://developers.cloudflare.com/workers-ai/models/llama-3.1-8b-instruct-fp8/)).

**Scheduling.** `npm run agent:run` is one bounded pass. The opt-in CT920 `scheduled` Compose profile runs it every 10 minutes and notification retries every 15 minutes. It is not started by the default web stack. From `deploy/ct920`, use `RELEASE_SHA="$(git -C ../.. rev-parse HEAD)" docker compose -p aeq-prod --profile scheduled up -d scheduler`; inspect counts with `docker compose -p aeq-prod --profile scheduled logs scheduler`. Set `AEQUITAS_EMAIL_OUTBOX_ENCRYPTION_KEY` to the same stable value in the app and scheduler environment (at least 32 bytes); the worker needs it to decrypt queued invitation/recovery messages. It receives no `SESSION_SECRET` or WebAuthn secrets. Each case is leased before a pass, revisited no sooner than 10 minutes later, and recovered after a 30-minute crashed-worker lease. A missing provider prevents new cases from being taken; already agent-managed cases can still close after consent or be handed back.

`npm run agent:status` also reports aggregate scheduler heartbeats for both scheduled operations and a sanitized reason when provider configuration is blocked (for example, a missing or mismatched terms-review identity). It marks a worker never observed, running, healthy, overdue, stalled, failed or interrupted; the rows contain only operation names, schedule intervals, outcomes, exit codes and timestamps, never case identifiers, party data, evidence or provider errors.

**Operator status.** `npm run agent:status` prints aggregate readiness, case-state, escalation, lease, notification, UTC-day model-call usage and scheduler heartbeat data; it omits case IDs, party details, evidence, addresses, provider errors and secrets. A recent healthy heartbeat shows the operation completed within two configured intervals; it cannot prove that the scheduler process did not stop immediately after its last heartbeat. Check the scheduled-profile logs for exact operational errors and the provider account for usage and billed cost.

## Evaluation

`npm run agent:evaluate -- --stub` exercises the harness offline. `--live` runs six synthetic fixtures against the configured provider, with at most one model call per fixture, and refuses to start unless `AEQUITAS_CASE_AGENT_EVAL_APPROVED=true`, which the operator sets after confirming the provider's data terms and spending limit. It also enforces the provider terms and Gemini billing gates above. It writes only to the `_test` database and a temporary local evidence directory, and suppresses outbound email. The evaluator can run before the quality-review attestation exists; the production case-agent resolver cannot. It emits an approval identity only when every automated fixture check passes.

After provider approval, add `--review-report=/tmp/aequitas-case-agent-review.json` to write a separate local review artifact. It contains the stored summary, reasoning, proposal, proposal-basis claims, claim-to-citation links, hash-verified cited excerpts, fixed party outcomes, a bounded sanitized `needs_human` request when valid JSON provides one, automated mechanics results, and blank human-review fields. It omits prompts, complete evidence files, case and party IDs, and credentials; common email, North American phone, and Canadian postal-code patterns are redacted, but redaction is not comprehensive. Keep the report local and review it with the owner, operator, counsel, and a Québec French reader as appropriate. Automated checks do not grade factual support, neutrality, legal suitability, or language quality; the report is not an approval or readiness decision.

After the live report has passed its automated checks and the appropriate humans have reviewed the generated text beside its cited excerpts, mark every checklist field `pass` only when that criterion actually passes, add any needed reviewer notes, and change the report's `status` to `human_review_complete`. Then run:

```sh
npm run agent:approve-evaluation -- --review-report=/tmp/aequitas-case-agent-review.json --confirm-human-review
```

The validator refuses stub reports, failed or incomplete fixtures, missing/unverified citations, party-isolation failures, escalated fixtures with recommendations, incomplete checklists, stale provider/account/model/prompt identities, and reports that have not been marked `human_review_complete`. It prints the exact `AEQUITAS_CASE_AGENT_EVALUATION_REVIEWED_FOR=...` assignment for the operator to configure; it does not edit environment files or call a provider. `--confirm-human-review` is an operator assertion: the tool validates the supplied JSON but cannot prove who reviewed it, whether the judgments are sincere, or whether counsel approved the program. Bump `AGENT_PROMPT_VERSION` whenever the prompt or model-output checks materially change; that automatically makes the old review stale.

- **Fixtures:** routine English; a routine dispute with a French-speaking complainant and English-speaking respondent; prompt injection with an English-speaking complainant and French-speaking respondent; a question needing legal interpretation; private-detail bait with the parties using different languages; and a material conflict between party accounts that the submitted records do not resolve.
- **Recorded per run:** provider, model, prompt version, model-call count, latency, prompt and response character counts, status, expected disposition, escalation reason, both issued outcomes, each party's fixed-text language, and whether each outcome cites only that party's own evidence. Provider-reported input, output and total token counts are summed only when the provider reported that field for every call. Missing or partial usage is identified; billed-currency cost is not available in this interface and must be checked in the provider's billing account.
- **Manual output review:** the optional `--review-report` artifact gives a reviewer the sanitized generated claims, including proposal-basis claims, beside excerpts from the exact hash-verified evidence spans, plus the party-specific fixed outcomes. Its checklist leaves semantic quality judgments blank for a human reviewer, including whether the proposed remedy is supported by its cited evidence. The automated `6/6` score measures workflow expectations and isolation mechanics only; it is not a model-quality score.
- **Results so far:** the prior five-fixture stub run passed 5/5 before the unresolved-conflict case was added and the prompt was bumped to `.3`. That prior result does not verify the current six-fixture set. **Live-model quality is untested.**

## Known limits

- **Test coverage:**
  - A stub stands in for the respondent's passkey enrolment.
  - Scanning in the routine integration tests is seeded; the browser test uploads through the real scanner in CI.
  - Page-number citation is verified end to end for searchable and OCR-extracted scanned multi-page PDFs.
- **Heuristic checks.** The deny list catches forbidden phrasing in staff-only model text; it cannot prove that text is accurate or neutral.
- **Escalation behaviour:**
  - Any model failure escalates at once; there is no retry budget.
  - Invitation and account-recovery messages use encrypted outbox fields on their token records. The exact provider payload (including recipient and one-time link) is AES-GCM encrypted with an HKDF-derived key from the distinct `AEQUITAS_EMAIL_OUTBOX_ENCRYPTION_KEY`, and authenticated to the message kind and record ID. It is cleared after provider acceptance, revocation, use, or expiration cleanup. The scheduled mail worker retries uncertain delivery no sooner than 15 minutes after the previous attempt, at most eight attempts, using the same payload and `invitation/{id}` or `recovery/{id}` idempotency key. Resend documents a 24-hour key-retention window ([idempotency keys](https://resend.com/docs/dashboard/emails/idempotency-keys)).
  - A permanently rejected or undecryptable invitation is not re-sent; an agent-managed case returns to staff. Definite recovery-email rejection revokes the recovery token. A pending recovery link expires after 30 minutes; the generic endpoint response does not reveal whether an account exists. Changing `AEQUITAS_EMAIL_OUTBOX_ENCRYPTION_KEY` makes queued payloads undecryptable and fails delivery closed, so the user must obtain a new invitation or recovery link. The bounded outbox does not replace real-host delivery checks or establish provider-side email retention.
- **Scope:**
  - One program per deployment. Roles are global, so this is not multi-organization software.
  - Two parties only. No retention or deletion service.

Section 3.3 addresses projects to acquire, develop or overhaul information systems or electronic services involving personal information and requires consultation with the privacy officer from the outset. If personal information is communicated outside Québec or an outside-Québec provider is entrusted to collect, use, communicate or retain it, s. 17 requires an assessment, adequate protection and a written agreement. Map the actual locations, access, logs and terms for the database, evidence storage, backups, email and model provider before any live case ([current Act, ss. 3.3 and 17](https://www.legisquebec.gouv.qc.ca/fr/document/lc/p-39.1); [CAI guidance on communications and providers outside Québec](https://www.cai.gouv.qc.ca/protection-renseignements-personnels/information-entreprises-privees/utilisation-communication-renseignements-personnels)).
- **Collection notice and party access.** Review whether notices explain the collection purposes and means, access and correction rights, consent withdrawal, recipients/categories and any possibility of communication outside Québec. Confirm that parties can obtain their computerized personal information in a structured, commonly used format; the Act addresses these points in ss. 8 and 3.3. Check this against the actual intake, consent, export and access flows ([current Act, ss. 3.3 and 8](https://www.legisquebec.gouv.qc.ca/fr/document/lc/p-39.1)).
- **Retention, destruction and complaints.** If the Act applies, s. 11 says personal information used to make a decision about a person is kept for at least one year after the decision. Section 3.2 also requires privacy-governance practices covering retention and destruction, staff roles throughout the information lifecycle and complaint handling, approved by the privacy officer and published in clear language. Decide which records meet s. 11 and reconcile the schedule with the append-only event log; no retention or deletion service exists yet ([current Act, ss. 3.2 and 11](https://www.legisquebec.gouv.qc.ca/fr/document/lc/p-39.1)).
- **Dispute-resolution framework and wording.** Determine whether the program is legally or contractually a mediation or other regulated process, who is accountable for proposals, and whether bilingual notices, consent wording, proposal language and the request-for-person path are adequate.
